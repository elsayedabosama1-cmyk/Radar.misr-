# مِرصد Android — الإدارة من داخل التطبيق فقط

## قرار معتمد
يجب أن يتمكن المستخدم من إدارة وتشغيل مِرصد بالكامل من داخل تطبيق Android نفسه، دون الحاجة إلى فتح GitHub أو أي لوحة استضافة أو قاعدة بيانات أو أداة تطوير أو تطبيق تقني خارجي.

## ما يجب أن يكون داخل التطبيق
- إدارة الأخبار: الإنشاء والتحرير والحفظ والمراجعة وإعادة التعديل والاعتماد والرفض والنشر والأرشفة وفق الصلاحيات.
- إدارة المستخدمين والأدوار والصلاحيات وتجميد/إعادة تفعيل الحسابات مع سجل تدقيق.
- إدارة مصادر الأخبار: إضافة وتعديل وتصنيف وتفعيل وإيقاف ومتابعة RSS/API وحالة الاتصال وآخر استيراد والموثوقية وحقوق إعادة الاستخدام.
- إدارة الأقسام والمجلدات والنصوص والصفحات والعلامات الإعلامية والصفحة الرئيسية والتقويم.
- لوحات تحليل المعلومات والجمهور والأداء الصحفي.
- إعدادات التطبيق والإشعارات والمزامنة والبيانات المحلية.

## تجربة الاستخدام
- واجهة إدارة موحدة داخل التطبيق، مع إظهار الأدوات بحسب دور المستخدم وصلاحياته.
- لا يُطلب من المستخدم إدخال GitHub Personal Access Token أو أي مفتاح تقني.
- لا تظهر للمستخدم النهائي خطوات إعداد قواعد البيانات أو الاستضافة أو النشر البرمجي.
- أي إعداد تشغيلي يحتاجه مدير النظام يجب توفيره من شاشة إعدادات آمنة داخل التطبيق، مع تحقق صلاحيات وتسجيل التغييرات.
- يجب أن تعمل الوظائف المحلية المتاحة دون إنترنت، وتُحفظ التغييرات في طابور مزامنة دائم، ثم تُزامن عند عودة الاتصال.
- لا يتم النشر العام أو اعتماد إجراء حساس اعتمادًا على صلاحية محلية غير متحقق منها؛ تُرسل العملية للخادم للتحقق والتنفيذ.
- تعرض الواجهة بوضوح حالة الاتصال والمزامنة والعمليات المعلقة وأي تعارض يحتاج تدخلًا.

## البنية التقنية
يمكن أن تستخدم البنية الداخلية خدمات مستضافة وقاعدة بيانات وواجهات API وأدوات تطوير، لكن تظل هذه تفاصيل خلفية يديرها فريق التطوير ولا تتطلب أي تعامل مباشر من المستخدم معها. يمنع تضمين أسرار أو رموز وصول إدارية في التطبيق أو كود الواجهة.

## معيار القبول
يُعد هذا الشرط محققًا فقط عندما يستطيع المستخدم تنفيذ مهام الإدارة اليومية المذكورة من التطبيق وحده، دون الرجوع إلى أي برنامج أو أداة تقنية خارجية.
